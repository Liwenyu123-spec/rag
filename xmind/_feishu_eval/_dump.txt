01-RAG评估
今天修改
RAG优化完毕后，必须进行评估。评估不仅能量化优化效果（比如：对比优化前后准确率提升了多少），还能帮你发现检索、生成环节的具体瓶颈。
一、为什么要评估RAG？
RAG 有三个核心环节都可能出问题，缺一不可评：
1.
检索（Retrieval）：召回的文档对不对、全不全？检索错了，后面再强的 LLM 也救不回来（garbage in, garbage out）。
2.
生成（Generation）：LLM 有没有忠实使用召回的资料？还是无视资料自己"编"（幻觉）？
3.
端到端（End-to-End）：抛开中间环节，最终答案到底准不准、是否切题、是否完整？
评估的目标：量化质量，定位瓶颈，驱动优化。

一个关键诊断思路：如果最终答案很差，先看检索指标——若检索就没召回正确文档，问题在检索侧（该优化分块/embedding/重排）；若检索召回了正确文档但答案仍错，问题在生成侧（该优化 prompt/上下文压缩/换模型）。

二、核心评估指标
RAG 评估指标分两大类，正好对应"检索"和"生成"两个环节。
2.1 检索质量（Retrieval Quality）
衡量"召回的文档对不对"，需要一份带标准答案的数据集（每个问题标注哪些文档/节点是正确的）。常用指标：



Hit Rate 和 MRR 是最常用、最易自动化的两个检索指标。LlamaIndex 的 RetrieverEvaluator 直接内置了它们。

2.2 生成质量（Generation Quality）
衡量"答案好不好"。LlamaIndex 把生成评估拆成三个互补的维度，关键优势是前两个不需要人工标准答案：



•
忠实度只关心"答案有没有出处"，哪怕答案恰好答错了问题但忠于资料，也算忠实——所以要和相关性一起看。
•
相关性关心"答没答到点子上"。
•
正确性需要人工标注的 reference 答案，最接近"考试打分"。
下面分别演示：检索评估（Hit Rate + MRR） 与 生成评估（Faithfulness + Relevancy + Correctness），全部使用 LlamaIndex 内置评估器，无需手写打分逻辑。
诊断思路：
答案差先看检索指标—— 检索没召回对，锅在分块 /embedding/ 重排；
检索对了答案还错，锅在 prompt / 上下文 / 模型。

3、检索质量评估：Hit Rate + MRR(Mean Reciprocal Rank[平均倒数排名])
生成评估只能告诉你"答案好不好"，但定位不了"是检索的锅还是生成的锅"。检索评估专门衡量"召回的文档对不对"。LlamaIndex 用 RetrieverEvaluator，并能用 LLM 自动生成"问题→正确节点"的评测数据集，省去人工标注。

"""
RAG 检索质量评估 - LlamaIndex RetrieverEvaluator
手动构造评测集 + 用 RetrieverEvaluator 算 Hit Rate 和 MRR

本脚本演示如何手动构建评估数据集，并通过自定义逻辑计算检索系统的两个关键指标：
1. Hit Rate (命中率): 检索结果中是否包含至少一个相关文档。
2. MRR (Mean Reciprocal Rank, 平均倒数排名): 第一个相关文档在检索结果中的排名倒数的平均值。
"""

import os

from llama_index.core import Settings, SimpleDirectoryReader, VectorStoreIndex

api_key = os.getenv("DASHSCOPE_API_KEY")

# 配置大语言模型 (LLM) 用于后续可能的生成任务或评估
Settings.llm = DashScope(model_name="qwen3.7-max", temperature=0, api_key=api_key)

# 加载本地文档数据
documents = SimpleDirectoryReader(input_files=["./data/company_info.txt"]).load_data()

# 使用句子分割器对文档进行分块，设置块大小和重叠部分以保留上下文信息

    def get_text_embedding_batch(
        self, texts: List[str], show_progress: bool = False
    ) -> List[List[float]]:
        """分批调用，每批 ≤ 10，避免 DashScope 报错"""
        BATCH_LIMIT = 10
        all_embeddings = []
        for i in range(0, len(texts), BATCH_LIMIT):
            batch = texts[i : i + BATCH_LIMIT]
            try:
                embs = self._inner.get_text_embedding_batch(
                    batch, show_progress=show_progress
                )
                if embs is None or len(embs) == 0:
                    raise RuntimeError("DashScope 返回空 embedding")
                all_embeddings.extend(embs)
            except Exception as e:
                print(f"❌ Embedding 批次失败 (batch {i//BATCH_LIMIT + 1}): {e}")
                raise
        return all_embeddings

四、Ragas 等专业评估框架（了解）
LlamaIndex 内置评估器适合快速、轻量地接入。如果要更系统、指标更丰富、可复现的基准评估，业界最主流的专门框架是 RAGAS。
4.1 RAGAS 是什么
RAGAS（Retrieval Augmented Generation Assessment）是一个专门为 RAG 流水线设计的自动化评估框架，核心理念有三点：
1.
Reference-free（多数指标免标注）：传统评估要为每个问题人工写标准答案，成本极高。RAGAS 的多数指标用 LLM-as-a-judge（大模型当裁判），让 LLM 对照"问题 / 答案 / 召回上下文"自动判分，无需人工标注就能算忠实度、答案相关性。
2.
检索 + 生成分别诊断：RAGAS 把指标明确归到"检索侧"和"生成侧"，方便定位瓶颈到底在哪一环——这正是 RAG 评估的关键诉求。
3.
与主流框架无缝集成：原生支持 LlamaIndex、LangChain，可以直接复用你已经搭好的 query engine、LLM 和 embedding，不用换技术栈。
4.2 RAGAS 核心指标
