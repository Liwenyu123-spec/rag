"先快速抓一车，再仔细挑最好的放最上面"\n你对超市导购说："我要做红烧肉"\n第一步：初始检索（召回）\n导购快速从整个超市抓回 50 样东西：\n•\n五花肉、酱油、冰糖、八角、桂皮、料酒、老抽、生抽、蚝油、盐、姜、葱、蒜、炖肉料包、红烧肉酱料包、预制红烧肉、红烧肉罐头、红烧牛肉面（？）、红烧排骨料、红烧鱼料、红烧豆腐料……\n特点：快、全、但乱 —— 结果\n(快但准度一般)           (缩小范围)        (慢但准度高)\n4.1、逐组件解读\nBi-Encoder（双塔，粗排用）：把"查询"和"文档"分别独立编码成向量，再算余弦相似度。文档向量可离线预计算，检索时只需算一次查询向量，所以快，适合从百万级文档里做第一轮召回，但精度一般。\nCross-Encoder（交叉编码，精排用）：把"查询 + 文档"拼成一对一起送进模型，让两者在每一层充分交互后直接输出相关性分数。准，但每个候选都要过一次模型，慢，只适合对少量候选（几十～几百条）做精排。\n4.2、为什么需要两阶段？\n如果只用 Bi-Encoder：快但不够准，Top-5 里常混入"沾边但不对"的内容。\n如果只用 Cross-Encoder：准但太慢，无法对百万文档逐一打分。\n\n##### FILE 1_定义_.txt #####\n两阶段结合：先用 Bi-Encoder 从海量文档中快速筛出几百个候选，再用 Cross-Encoder 对这少量候选精细打分，兼顾效率与效果。\n\n##### FILE 2_通俗例子.txt #####\n4.3、总结：\nBi-Encoder 负责"找得快"，Cross-Encoder 负责"排得准"。\n两阶段检索是工业级 RAG 系统的标准配置（粗召回 + 精排）。\n\n##### FILE 4_核心原理.txt #####\n5、代码：\n依赖安装：\n# 方式 A（API 重排，推荐，与本章 embedding 同源）\npip install llama-index-core llama-index-embeddings-dashscope llama-index-postprocessor-dashscope-rerank\n# 方式
