一、什么是 Corrective RAG？
当RAG系统的检索环节"失手"时,系统应该具备"自知之明"和"自我纠错"能力。CRAG通过引入轻量级评估器和动态知识纠错机制,让RAG从"盲目依赖检索"进化为"智能评估+按需纠错",在多个基准测试中将检索增强生成的准确率提升了4%-37%,且无需对现有LLM进行额外训练。
1、背景铺垫
想象一下,你在准备一场演讲,你的助手帮你找了一些资料。如果助手找来的资料很靠谱,你的演讲会很精彩;但如果助手找来的资料是错的或者不相关的,而你还完全照搬,那后果就不堪设想了。
这就是当前RAG面临的困境:
•
问题本质: RAG把"检索器"找来的文档当作"绝对真理",无条件喂给生成器使用
•
现实挑战: 检索器不是完美的,它可能因为查询表述不清、知识库覆盖不全、语义理解偏差等原因,返回不相关甚至误导性的内容
•
现有局限: 大多数RAG方法对检索结果"照单全收",没有质量评估机制。就像你拿到一份资料不先看看质量如何就直接使用,风险很大

检索到的文档不相关、不完整、错误 → 导致大模型回答胡说八道（幻觉）

    @step
    async def ingest(self, ctx: Context, ev: StartEvent) -> StopEvent | None:
        """传入 documents 时：建索引并返回 index。"""

七、实战启示
对工程实践的指导
1.
不要迷信检索器: 你的检索器再厉害,也会有翻车的时候。在RAG系统中加入质量评估和纠错机制是必要的"安全带"
2.
轻量级评估优于大模型: 专门训练的0.77B评估器在判断相关性上明显优于ChatGPT。这告诉我们,专业任务用专业模型,不要总想着用"大而全"的LLM做所有事
3.
动态知识比静态知识更可靠: 当内部知识库无法回答时,果断转向外部搜索,不要让模型"闭门造车"产生幻觉
4.
知识粒度很重要: 整篇文档直接喂给LLM效果往往一般,拆分成片段后再筛选,效率更高
具体应用场景
•
企业问答系统: 当企业知识库的文档匹配度低时,CRAG会自动搜索互联网权威来源,避免"不懂装懂"
•
医疗咨询: 医疗领域的准确性要求极高,CRAG的知识精炼和网络搜索机制可以显著降低错误信息
•
教育辅导: 学生提问时,如果检索结果不理想,系统可以动态获取最新资料,提供更准确的答案

一、什么是 Corrective RAG？
当RAG系统的检索环节"失手"时,系统应该具备"自知之明"和"自我纠错"能力。CRAG通过引入轻量级评估器和动态知识纠错机制,让RAG从"盲目依赖检索"进化为"智能评估+按需纠错",在多个基准测试中将检索增强生成的准确率提升了4%-37%,且无需对现有LLM进行额外训练。
1、背景铺垫
想象一下,你在准备一场演讲,你的助手帮你找了一些资料。如果助手找来的资料很靠谱,你的演讲会很精彩;但如果助手找来的资料是错的或者不相关的,而你还完全照搬,那后果就不堪设想了。
这就是当前RAG面临的困境:
•
问题本质: RAG把"检索器"找来的文档当作"绝对真理",无条件喂给生成器使用
•
现实挑战: 检索器不是完美的,它可能因为查询表述不清、知识库覆盖不全、语义理解偏差等原因,返回不相关甚至误导性的内容
•
现有局限: 大多数RAG方法对检索结果"照单全收",没有质量评估机制。就像你拿到一份资料不先看看质量如何就直接使用,风险很大











这张图展示了 Corrective RAG（CRAG） 的核心思想：检索后评估文档质量，区分"准确文档"和"不准确文档"，只使用准确文档来生成答案。
左侧：准确文档 → 正确回答 ✅

class CorrectiveRAGWorkflow(Workflow):
    @step
    async def ingest(self, ctx: Context, ev: StartEvent) -> StopEvent | None:
        """传入 documents 时：建索引并返回 index。"""
        documents = ev.get("documents")
        if documents is None:
            return None
        index = VectorStoreIndex.from_documents(documents)
        return StopEvent(result=index)

    @step
    async def prepare_for_retrieval(self, ctx: Context, ev: StartEvent) -> PrepEvent | None:
        """传入 query_str/index 时：把 LLM、index、Tavily 工具存进上下文。"""
        query_str = ev.get("query_str")
        if query_str is None:
            return None
        await ctx.store.set("index", ev.get("index"))
        await ctx.store.set("tavily_tool", TavilyToolSpec(api_key=ev.get("tavily_ai_apikey")))
        await ctx.store.set("query_str", query_str)
        return PrepEvent()

    @step
    async def retrieve(self, ctx: Context, ev: PrepEvent) -> RetrieveEvent:
        """检索候选节点。"""
        query_str = await ctx.store.get("query_str")
        index = await ctx.store.get("index")
        nodes = index.as_retriever(similarity_top_k=5).retrieve(query_str)

七、实战启示
对工程实践的指导
1.
不要迷信检索器: 你的检索器再厉害,也会有翻车的时候。在RAG系统中加入质量评估和纠错机制是必要的"安全带"
2.
轻量级评估优于大模型: 专门训练的0.77B评估器在判断相关性上明显优于ChatGPT。这告诉我们,专业任务用专业模型,不要总想着用"大而全"的LLM做所有事
3.
动态知识比静态知识更可靠: 当内部知识库无法回答时,果断转向外部搜索,不要让模型"闭门造车"产生幻觉
4.
知识粒度很重要: 整篇文档直接喂给LLM效果往往一般,拆分成片段后再筛选,效率更高

企业问答系统: 当企业知识库的文档匹配度低时,CRAG会自动搜索互联网权威来源,避免"不懂装懂"
•
医疗咨询: 医疗领域的准确性要求极高,CRAG的知识精炼和网络搜索机制可以显著降低错误信息
•
教育辅导: 学生提问时,如果检索结果不理想,系统可以动态获取最新资料,提供更准确的答案
