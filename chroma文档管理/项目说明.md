# 搜索引擎项目说明（chroma文档管理）

对照国庆作业第 1 条：**基础 RAG → 前/中/后模块化优化 → Self-RAG / CRAG → 评估**。  
交作业演示请用页面上的 **「RAG 知识库问答」**，接口是 `POST /ask`。

启动：

```powershell
python chroma文档管理/run.py
```

浏览器打开：http://127.0.0.1:8003/  
接口文档：http://127.0.0.1:8003/docs

---

## 1. 整体在干什么

这是一个 **LlamaIndex + Chroma + 大模型** 的知识库问答服务：文档切块入库，提问时检索相关片段再生成答案。  
和课堂 `ModularRAG` 一样，各优化做成 **可开关模块**，前端勾选或选预设后，由 `RagAskService.ask` 按顺序组装。

主链路（`/ask`）：

```
用户问题
  → [可选] Self-RAG Retrieve：要不要查库？闲聊可直接答
  → [检索前] 清洗 / 重写 / HyDE / Step-Back
  → [检索中] 向量检索；可选 BM25 + 融合；可选 Multi-Query
  → [检索后] 重排 / 压缩 / 长上下文重排
  → [可选] CRAG：滤无关；全无关则改写再检
  → 大模型根据资料生成答案
  → [可选] Self-RAG ISSUP 验据（不足则按资料重写）+ ISUSE 打分
  → [可选] 生成质量评估 Faithfulness / Relevancy / Correctness
```

`/search`、`/query`、`/chat` 仍是偏基础的检索或问答，**不跑完整勾选链路**。

## 3. 按作业模块细说

### 3.1 基础 RAG（`engine.py`）

- 读配置，初始化 Embedding、LLM、Chroma collection。
- 文档 → 分块（sentence / token / semantic）→ 写入向量库。
- `search`：只检索相似片段。
- `query` / `chat`：检索 + 生成（多轮带会话记忆）。
- 库空时会 seed 示例，并尝试加载 `data/` 目录。

这是「没有勾选任何高级优化」时的底座。

### 3.2 检索前（`pre_retrieval.py`）

在向量检索之前改查询，对应讲义 Pre-Retrieval。

| 策略 | 行为 |
|------|------|
| `none` | 原问题直接检索 |
| `clean` | 去口语填充、标点，术语替换（如「扣钱」→「扣款」） |
| `rewrite` | 清洗后再让 LLM 改写成更适检索的问句；**清洗句 + 改写句双路**，防改歪 |
| `hyde` | 生成假想说明文再检索；**清洗句 + 假想文档双路**；假想文不当引用 |
| `step_back` | 把具体问题抽象成上位问题再检索；**清洗句 + 上位句双路**（讲义 1.4 算子） |

前端：勾选「检索前优化」并选下拉策略。

### 3.3 检索中（`retrieval_optimize.py` 前半）

- **向量检索**：语义相似。
- **BM25 + jieba**：关键词匹配。
- **QueryFusionRetriever**：两路融合；`fusion_mode` 常用 `reciprocal_rerank`（RRF），`simple` 为简单拼接。
- **`num_queries > 1`**：Multi-Query，让 LLM 生成多个查询变体再融合（对齐 ModularRAG）。

前端：勾选「混合检索」并选融合方式；勾选「Multi-Query」。

### 3.4 检索后（`retrieval_optimize.py` 后半）

召回之后、生成之前：

- **重排**：默认本地 bge Cross-Encoder；也可配 DashScope rerank。
- **上下文压缩**：按句子相关度丢掉不相关句（中文分句）。
- **长上下文重排**：重要内容放到上下文两端，减轻「中间遗忘」。

前端：三个「检索后」勾选框。

### 3.5 CRAG（`crag.py`）

作业里的 Corrective RAG（**库内修正版**）：

1. 对每篇召回结果判 `RELEVANT` / `IRRELEVANT`，丢掉无关。
2. 若全部无关：改写问题，再检索、再过滤一轮。
3. 仍无关则拒答。

**没有**接 Tavily 外网搜索。前端勾选「Corrective RAG」。

### 3.6 Self-RAG（`self_rag.py`）

工程复现（判断点单独问 LLM），不是论文里微调 token 的模型：

| 步骤 | 作用 |
|------|------|
| Retrieve | 要不要查库？问候/闲聊可 `NO`，直接用模型答 |
| ISREL | 资料相关吗？与 CRAG 过滤同构；**两者都开时共用一次**，少烧钱 |
| ISSUP | 答案有没有被资料支撑？`PARTIALLY`/`NO` 则按资料重写 |
| ISUSE | 对用户有用程度 1～5，展示用 |

前端勾选「Self-RAG」（默认关）。

### 3.7 评估（`rag_eval.py` + 路由）

**生成质量**（问答时勾选「生成质量评估」）：

- Faithfulness：有没有瞎编（看是否忠于召回上下文）
- Relevancy：有没有答到点子上
- Correctness：填了「标准答案」才算，约 1～5 分

页面会给一句诊断：答案差先看检索还是生成。

**检索质量**（按钮「跑 Hit Rate / MRR」→ `POST /eval/retrieval`）：

- Hit Rate：Top-K 里是否至少命中相关文档（用关键词近似标注）
- MRR：第一个相关文档排名的倒数平均

默认题库对应 `data/company_info.txt`（贝壳科技示例，带干扰信息）。评测前请保证该文档已入库。

### 3.8 预设（`presets.py`）

对齐课堂 `ModularRAG.PRESETS`：

| 预设 | 含义 |
|------|------|
| `basic` | 混合检索 + 简单融合，几乎无前后处理 |
| `hybrid_search` | 向量 + BM25，RRF 融合 |
| `advanced` | 重写 + Multi-Query + 重排 + 压缩 + 长上下文重排 |
| `full_optimization` | HyDE + 上一条 + CRAG |
| `step_back` | Step-Back 上位问题 + 混合检索 + 后处理 |
| `custom` | 自己勾选；未勾的项跟 `rag_config.yaml` |

选预设会改左侧开关；再改勾选会回到「自定义」。

### 3.9 编排层（`rag_service.py`）

唯一把上面拼起来的地方：`RagAskService.ask`。  
优先级：**请求体显式字段 > 命名预设 > `rag_config.yaml` > `.env`**。

`GET /modules` 按 YAML 默认画出当前 Module Type → Module → Operator，以及 Linear / Branching / Conditional / Loop 流程标签。

`main.py` 的 `/ask` 只做参数校验，然后调它。返回里带 `pre_retrieval`、`crag`、`self_rag`、`generation_eval`、`optimizations`，给前端展示「这次实际开了什么」。

## 4. 前端怎么对应

页面左侧（仅「RAG 知识库问答」模式）：

- 预设下拉
- 检索前 / 混合 / Multi-Query / 重排 / 压缩 / 长上下文 / CRAG / Self-RAG / 生成评估
- 评估可填标准答案；「跑 Hit Rate / MRR」单独测检索

其它模式：

- 多轮问答 → `/chat`
- 一次性问答 → `/query`（带来源，无完整优化勾选）
- 语义搜索 → `/search`（不调大模型）

---

## 5. 主要接口

| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/ask` | 作业主接口：勾选/预设 + 问答 + 过程信息 + 可选生成评估 |
| POST | `/eval/retrieval` | Hit Rate / MRR |
| POST | `/search` | 只检索 |
| POST | `/query` | 基础一次问答 |
| POST | `/chat` | 多轮 |
| POST | `/ingest` 或上传 | 文档入库 |
| GET | `/modules` | Modular RAG 三层抽象 + YAML 默认编排 |
| GET | `/health` | 模型与文档数 |

`/ask` 常用字段：`question`、`k`、`preset`、`use_pre`、`strategy`（含 `step_back`）、`use_hybrid`、`fusion_mode`、`num_queries`、`use_rerank`、`use_compress`、`use_reorder`、`use_crag`、`use_self_rag`、`use_eval`、`reference`。

## 6. 交作业可以怎么讲（2 分钟）

1. 打开页面，选 `full_optimization` 或自己勾选，问知识库里的题，指出答案下来源和「本次优化」标签。  
2. 勾上 Self-RAG，问「你好」，说明 Retrieve=NO、未检索。  
3. 勾上生成评估（可选填标准答案），讲 Faithfulness / Relevancy。  
4. 点 Hit Rate/MRR，说：答案差先看检索指标，检索差调分块/混合/重排，检索好再查生成。  
5. 指代码：前 `pre_retrieval`、中后 `retrieval_optimize`、纠错 `crag`、反思 `self_rag`、串起来 `rag_service`、评估 `rag_eval`。

---

## 7. 明确没做的（避免被问住）

- CRAG **不联网**，没有 Web/Tavily。  
- Self-RAG **不是**微调 `selfrag_llama2` 那种 token 级模型。  
- 没有一键「基础 RAG vs 优化 RAG」批量对比表，可两次不同预设各评一次自己对比。  
- `/query` `/chat` 未接完整优化开关。
